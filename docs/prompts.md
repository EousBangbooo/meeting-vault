# 提炼提示词

直接复制给能读本地文件的 AI 用（Claude Code、Codex、Cursor、任何 agent）。

四个提示词对应四个动作：**入库 / 提炼 / 回填 / 检索**。

---

## 1. 处理新会议

打开本地 `会议处理.html`，在指定会议下点「复制审阅指令」。这句指令会让 AI 读取[单场会议审阅](review-guide.md)和指定转写。

---

## 2. 提炼五类资产

```
你是我的知识库编辑。会议库路径：<VAULT>，原文在 raw/meetings/。

任务：把最近 N 场（或指定日期范围）会议，提炼成五类资产。已有内容先读，**只增量补充，不重写**。

五类资产与要求：

【方法论】只收"换个项目也成立"的做法。每条格式：
  做法一句话 → 适用条件 → 反例（可选）
  不要把具体参数（日期、频率、人数）写进来。

【问题清单】按"提及该问题的会议数"排序。
  每条：问题 → 覆盖场次 → 根因判断（你的推断要标「推断」）

【事件库】同类事件的处理方式与结果。
  每条：事件类型 → 处理方式 → 结果 → 出处日期

【未完成】会上定了但没有任何一场会确认闭环的。
  每条：事项 → 首次出现 → 最后提及 → 现状

【决策日志】只追加，不改旧条目。

硬规则：
- 每条结论必须带出处（日期，能带时间码更好）。没有出处的不要写。
- 区分「会上说的」和「你的推断」，推断必须标注。
- 同一件事在不同会议上说法矛盾时，不要选一个，把矛盾列出来。
- 不确定的写「待确认」，不要猜。
```

---

## 3. 回填决策结果

```
任务：更新 knowledge/决策日志.md 里「待观察」的条目。

对每一条：
1. 在 raw/meetings/ 里找它之后发生的会议，看有没有提到这件事的结果。
2. 有明确结果 → 改成「已验证」或「已推翻」，写清结果和依据（日期）。
3. 只有间接迹象 → 状态改「部分验证」，写清看到了什么。
4. 完全没有 → 保持「待观察」，复核日顺延 30 天。

禁止：把"没人再提"当成"已完成"。
如果一条决策连续 3 次复核都没有结果，标记「无下文」，这本身是个结论。
```

---

## 4. 检索

```
任务：回答我的问题，基于 raw/meetings/ 和 index/。

要求：
1. 先给结论，再给依据。
2. 依据格式：`日期 时间码` + 一句原话（不超过 40 字）。
3. 找到多场时，按时间排序，标出哪场最关键。
4. 找不到就说找不到，不要用相似内容凑。
5. 如果问题涉及"现在该怎么做"，把「当时的事实」和「现在的建议」分开写。
```

---

## 反模式（这些做法会让知识库变脏）

| 做法 | 为什么错 |
|---|---|
| 每场会都写纪要 | 90% 的会没有决策，写了也没人看，还稀释信号 |
| 把参数当方法 | 参数一改，整页作废 |
| 用"大家要加强沟通"当结论 | 不可执行，无法验证 |
| 只记成功案例 | 反例才是防止重犯的部分 |
| 把推断写成事实 | 三个月后没人分得清哪句是会上说的 |
| 同一天多场合并成一份 | 丢了"哪场定的"这个关键信息 |
